# 记录按需加载

UmaShow 1.4.47 对接 UmaAutoResearch 0.1.5 的分页接口。桌面端及手机／网页端共用 `HistoryTab` 和 `useHistoryPages`，保留现有卡片、Tab、图表布局。

- 进入记录只请求当前视图。日期和任务使用 `/api/account/career/history/page/query`，每页 10 个完整日期／任务分组。
- 进入追踪后使用 `/api/account/career/history/tracking/query`，只请求当前指标，每页 30 条。宝石、两种招募券、能量饮料各自保存分页状态。
- 滚动接近列表底部时自动携带服务器返回的 `next_offset` 懒加载下一页；没有下一页时停止触发。记录按 ID、追踪按业务日合并，避免分页边界变化产生重复项。
- 切换内部 Tab 复用本次查看期间已加载的结果；刷新当前 Tab 从第一页重取。账号／服务器切换、外部刷新或离开记录页面后重新加载，旧请求不能覆盖新账号数据。
- 列表不预取 run。点击记录继续使用 `/api/account/career/history/detail/query`，详情汇总覆盖该日期／任务的完整数据，不受列表分页影响。
- 追踪直接使用后端的 `value` 和 `delta`，不会把未请求的指标填为零，也不会在页边界重算差值。
- 登录及读取云端配置不再附带历史查询。旧的组合查询接口不作为分页失败时的回退；请求失败可在当前 Tab 重试。

仅做类型检查，不运行测试。当前服务需已运行提供新接口的后端版本。
