# 赛程规划

顶栏「记录」旁的「规划」页面在本地计算赛程，无需账号登录或后端接口。目前界面仅支持荣耀女神杯。

## 文件分工

- `src/renderer/utils/raceScheduleOptimizer.ts`：独立核心算法，导出 `optimizeRaceSchedule(input)`；不依赖 React、存储或数据库。
- `src/renderer/utils/raceWinRateModel.ts`：固定参考胜率表。界面不展示模型，不提供编辑、恢复或来源选择；旧设置中的胜率覆盖值不再加载。
- `src/renderer/utils/raceInheritanceRecommendation.ts`：枚举六个红因子槽位内的初始适应性改造，比较赛程收益；同收益优先减少因子需求。
- `src/renderer/utils/racePlannerCatalog.ts`：主数据库资料转换、剧本赛历和固定目标。
- `src/renderer/components/autoResearch/RacePlanningTab.tsx`：头像选择、系统推荐因子、统一的比赛与休息日历、列表／日历结果及导出。复用种马选择、因子星级与赛程组件。
- `.erb/scripts/generate-race-planner-rankings.ts`：离线预计算所有马娘的三种目标排名，输出 `race_planner_rankings.json`。运行 `npm run update:race-planner-rankings` 可单独重算；`update:race-planner` 会同时更新赛历和排名。
- `python/generate_race_planner_data.py`：生成赛历、冠军粉丝奖励、初始适应性和生涯目标；运行 `npm run update:race-planner`，也已纳入 `update:game`。

生成的 JSON 包含数据库 SHA-256，方便追溯数据版本。默认使用本地国服 `master.mdb`。

## 核心接口与递推

输入包括候选比赛、起止回合、改造后适应性、胜率表、优化目标、重赏级别下限、粉丝加成、固定比赛、禁赛日期和固定休息日期。固定比赛使用 `回合 -> 候选比赛 ID 数组`；同一回合的多个候选表示任选其一，界面手动固定时将其收窄为单个比赛。

令 `F(t, s)` 为第 t 回合结束、已连续参赛 s 场时的最优累计收益。初始收益为零，初始连战数为零。

- 不参赛：`F(t, 0) = max_s F(t-1, s)`。
- 参赛：从 `F(t-1, s)` 转移到 `F(t, min(s+1, 6))`，加上该场期望收益。
- 单局期望粉丝为 `Σ(胜率 × 冠军基础粉丝) × (1 + 支援卡粉丝加成 / 100) × 1.10 + 比赛外剧本粉丝`。1.10 为作者经验修正，比赛外剧本粉丝暂设为 0；普通赛、生涯目标赛、年末自动剧本赛的比赛粉丝都使用同一乘数。基础粉丝列保留数据库原始奖励，逐场期望粉丝、累计值、总数与排行榜包含修正。
- 胜场收益为所选级别比赛的胜率；其他级别为零。GI/GII/GIII 的数据库级别分别为 100/200/300，EX 不算重赏。
- 固定比赛回合禁止不参赛；禁赛回合禁止自由参赛，但允许剧本固定比赛；固定休息与固定比赛冲突时报错。

胜率按用户提供图片中的场地／距离适应性合计与连战次数查表。AA 至 GG 的基础百分比分别取图中代表列 AA、AB、AC、AD、AE、AF、AG、BG、CG、DG、EG、FG、GG；合计适应性相同的组合胜率相同，交换场地与距离不改变结果，S 按 A 计算。图中 AA 的 110%／105% 在实际概率计算时封顶为 100%。胜率表的列是 1–2、3、4、5、6+ 连战，故 6 场以后的状态可合并。空白胜率表示未知，只排除相应转移，不把未知当作零胜率。合法的零胜率仍允许参赛。

生涯目标赛通过赛历上的 `isCareerGoal` 标记，查胜率时固定使用当前适应性的 1–2 连战档，不受连战次数影响。该标记与手动固定比赛区分，手动固定的普通赛仍使用实际连战档。目标赛继续累计连战次数，不替前后普通赛重置连战；普通掉落模型的连战掉率规则保留。年末三场自动剧本赛仍按必成功、每场 5% 掉落单独处理。

每个状态保留最优路径及前驱，结束后回溯完整赛程。挂钻首先最大化期望掉落次数，掉落收益相同时最大化期望粉丝；两者均相同时才依次比较 GI、GII、GIII 期望胜场。其他目标首先比较对应期望收益，再比较高级别重赏胜场与另一目标，最后减少参赛次数。此顺序在赛程优化、继承推荐与离线排行榜中一致。时间复杂度为 `O(回合数 × 7 × 每回合候选比赛数)`。粉丝数按数据库冠军基础奖励、胜率与粉丝加成计算，不会仅因级别更高而选择粉丝期望更低的比赛。

胜场统计级别仅在胜场目标下显示，默认 GI；粉丝和掉钻目标按 GI 口径展示胜场统计，不用该选项过滤候选比赛。列表与 CSV 展示数据库中的冠军基础粉丝数，来自 `single_mode_program.fan_set_id` 对应的 `single_mode_fan_count` 第一名奖励，便于与加成后的期望收益核对。

## 剧本及模型范围

女神杯规划至高级年 12 月下半。GUR、WBC、SWBC 分别在第 24、48、72 回合结束后自动举行，保留当回合的正常比赛或休息安排。按用户指定口径，这三场均视为成功的剧本重赏，每场期望掉落 0.05，合计 0.15，同时计入冠军粉丝奖励和胜场。它们不增加或打断普通赛程连战，不套用普通比赛的连战胜率与掉率。结果与 CSV 按发生顺序单独列出，界面标记「剧本」。

底层赛历仍支持其他剧本以供既有功能调用。主数据库中 `determine_race_for_generate=99` 的条件替换目标不与默认目标同时导入，避免将分支路线错误地视为必须同时完成的目标。

非冠军粉丝收益近似为零。模型不模拟属性成长、训练效果、通关失败、报名粉丝门槛或非比赛类目标。界面提示报名门槛与期望粉丝的差距，并展示其他生涯目标；这些提示不代表已保证实际可报名或达成目标。粉丝总数是规划区间内的期望比赛收益，不是完整育成最终粉丝数。

系统自动推荐继承需求，初始适应性提升 1／2／3／4 级分别至少需要同类红因子 1／4／7／10 星，每槽最多 3 星，合计最多六槽，最多升至 A。不模拟中途继承成功，S 与 A 使用相同胜率。修改设置后自动重新优化。

排行榜按女神杯、默认生涯路线、固定参考胜率、GI 胜场口径、零粉丝加成与无手动约束离线生成，已包含 1.10 经验修正。显示时按当前支援卡加成与生成时加成的比例换算粉丝，1.10 不重复相乘；掉钻与胜场视图也显示对应的期望粉丝列。粉丝加成是所有比赛共同的正乘数，不改变这三种目标的排名或最优路径。使用方案保留当前粉丝加成，应用角色、路线及其他标准参数，选中后关闭排行榜。

规划页粉丝加成默认 120%，修改后持久化；切换角色、目标或使用排行榜方案不会清零。旧版自动保存的默认 0 迁移为 120%，新版本手动设置的 0 仍正常保存。只有显式重置规划才恢复默认值。

「复制参赛计划」只导出额外参赛安排，目标赛和自动剧本赛不写入额外赛程；CSV 包含固定赛、休息回合、剧本赛、每场胜率、期望粉丝、累计期望重赏胜场与期望掉落次数。

## 离线配置的一键设计

新建离线详设时选择「种马 / 挂钻 / 刷粉丝」。赛程来源可选游戏 API 槽位或自行配置，保存于 `CareerSetting.offline_design`；直接启动、保存配置启动、任务队列与 Web 云配置使用相同的请求转换。

育成马娘选择列表展示初始适应性；已选卡片根据两侧父辈及四位祖辈的实际红因子更新适应性，变化项以黄色背景标记。初始继承按 1/4/7/10 星提升 1/2/3/4 级，最高提升至 A；原有 A/S 不降低。清除或更换继承马娘时立即重新计算。已选继承位复用完整因子、祖辈与详细因子查看组件。

挂钻与刷粉丝固定为荣耀女神杯。一键设计使用赛程 DP，保留生涯目标及已保存的手动固定赛。`offlineCareerDesign.ts` 负责选种马和编排：只从自己的继承马娘中统计两侧父辈与祖辈的六个槽位，筛选满足红因子需求的合法组合，再最大化红蓝星数总和（同分优先蓝星）。一键设计排除借用马娘；手动选择仍可借用一位。父辈不能与育成角色或彼此同角色。

没有满足条件的组合时，展示所有不同的两侧红因子分配方案和五类蓝因子建议，填入按目标适应性计算的赛程，并清空父辈选择，补齐后才能启动。已匹配时按实际红因子星数推导初始适应性，不假设中途继承成功。

`raceJewelModel.ts` 独立维护掉落模型：期望掉落次数 = 胜率 × 胜利条件下的掉率；暂定前三连战为 5%，第 4 连战起为 4%。它优化的是掉落事件次数，不是钻石数量。此目标也可在「规划」Tab 使用；当前胜率来源仍为参考表。

请求的 `race_source` 为 `api` 时启动读取游戏槽位；为 `custom` 时使用 `race_array`，包括显式空数组。旧客户端不传来源时保留历史行为。结果观察的初始元数据同时保存实际使用的赛程、赛程来源及配置，便于后续分析。
